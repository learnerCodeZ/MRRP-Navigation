# 笔记：MRTK 原生 UI 重构（替换坏掉的 Unity UI 菜单）

> 日期：2026-07-19
> 背景：HL2 上原 Unity UI 菜单（Screen Space Canvas + UnityEngine.UI.Button）AirTap 不灵、不能拖/缩。改用 **MRTK 原生组件**（PressableButton + ObjectManipulator + BoundsControl）重搭。
> 配套：`docs/MRReP_UI_Design_Guidelines.md`（视觉规范）、`docs/MRReP_菜单与画线交互规范.md`（交互逻辑）。

---

## 0. 为什么重构

| | 旧（Unity UI） | 新（MRTK 原生） |
|---|---|---|
| 按钮 | `UnityEngine.UI.Button`（鼠标向） | **`PressableButton`**（原生捏/AirTap） |
| 拖动 | 无 | **`ObjectManipulator`** |
| 缩放 | 无 | **`BoundsControl`** |
| 设备(HL2) | AirTap 不灵、像全息影子 | 原生支持捏/点/拖/缩 |
| 渲染 | Screen Space/Unity EventSystem(鼠标) | World Space/MRTK 输入系统(手) |

旧 UI 为 Editor 鼠标测试而做，HL2 上不工作（详见 [[PartII_HL2真机打通-20260719]] 坑10）。MRTK 原生组件才是 HL2 正解。

---

## 1. 设计（对齐 UI 规范）
- **条状面板**（贴手腕或眼前方），藏青半透明 + 圆角 + 白描边。
- **按钮**：白胶囊，图标左+文字右；激活态青色。
- 两个菜单：MainMenu（Preferred Path + Settings + 留白）/ PreferredPathMenu（Back / Clear / Send / Add）。
- **可拖**（ObjectManipulator）/ **可缩**（BoundsControl）。

---

## 2. 代码侧（已就绪，不用改）
控制器逻辑方法已现成，按钮事件直接接这些：
- `PreferredPathMenuController`：`OnAddClicked()` / `OnClearClicked()` / `OnSendClicked()`
- `MainMenuController`：`OnBackClicked()`（或 PreferredPath 的 OnBack）

> 这些都是 public，能在 Inspector 的 UnityEvent 里选。

---

## 3. 重构步骤（Unity 编辑器里做）

### 3.1 找 MRTK 预制体
MRTK 2.8 预制体在 Package Manager → MRTK Foundation → Samples，或路径：
`Packages/com.microsoft.mixedreality.toolkit.foundation/SDK/Features/UX/Prefabs/`
- **按钮**：`PressableButton_32x32mm_IconAndText`（或 `PressableButtonHoloLens2`），在 `Buttons/`。
- **面板/菜单**：`Slate` 或 `NearMenu`（自带 ObjectManipulator/BoundsControl）。

### 3.2 建面板
- 拖一个 `Slate`/`NearMenu` 预制体到场景（自带可拖可缩）。
- 或建空物体 + 加 `ObjectManipulator`（拖动）+ `BoundsControl`（缩放）。
- 设位置：眼高前方（如 `(0, 1.4, 1.5)`）。

### 3.3 加按钮（4 个）
- 拖 `PressableButton_32x32mm_IconAndText` 到面板下，复制 4 个。
- 重命名 + 改 Label + Icon：
  - `Add` → 文字 "Add"、图标 `+`
  - `Clear` → "Clear"、`✕`
  - `Send` → "Send"、线框卡车
  - `Back` → "Back"、`←`

### 3.4 接线（关键）— 按钮事件 → 控制器方法
每个按钮的 **PressableButton** 组件（或其 `Interactable`）→ 找 **OnClicked()** 事件区 → `+` 添加 →
- **Object** 槽：拖入挂 `PreferredPathMenuController`（或 MainMenuController）的物体。
- **Function** 下拉：选对应方法：
  - Add 按钮 → `PreferredPathMenuController.OnAddClicked`
  - Clear → `OnClearClicked`
  - Send → `OnSendClicked`
  - Back → `MainMenuController.OnBackClicked`（或 PreferredPathMenuController.OnBack）

### 3.5 清理旧 UI
- 隐藏或删除旧的 Unity UI Canvas 菜单（`MainMenu`/`PreferredPathMenu` 的旧 Canvas/Button），避免和新 MRTK 菜单冲突。
- 注意：`MainMenuController`/`PreferredPathMenuController` 脚本**保留**（逻辑在新菜单用），只删旧 Canvas 视觉。

### 3.6 关掉"自动模式"（按钮好了再做）
现在为绕过坏 UI，`HandTracker` 开了**自动画线 + 停笔自动发送**（设备专用）。MRTK 按钮能用了之后，把自动模式关掉，改回靠按钮触发：
- `HandTracker`：注释/删掉 `Start()` 里的 `StartTracking()` 和 `DoAutoSend()` 调用（`#if !UNITY_EDITOR` 块）。
- 这样：用 MRTK 按钮点 Add 进画线、点 Send 发送（流程正常），不再自动。

---

## 4. 验证
- Build + Deploy 到 HL2。
- AirTap 按钮 → 灵敏响应（Add/Clear/Send/Back）。
- 面板能用手拖动（ObjectManipulator）、能缩放（BoundsControl）。
- 点 Add → 画线（AirTap 地板放点）→ 点 Send → 车走。

---

## 5. 关键认知
- **HL2 上的 UI 必须用 MRTK 原生组件**（PressableButton/Interactable），不能用 UnityEngine.UI.Button（那是鼠标向）。
- **ObjectManipulator = 拖动，BoundsControl = 缩放**——MRTK 现成组件，挂上即可。
- **控制器逻辑（OnAddClicked 等）已 public**，按钮事件直接接，不用改代码。
- **重构是 Unity 编辑器工作**（放预制体 + 接事件），不是代码——代码侧已就绪。
- **改完关掉自动模式**（HandTracker 的 auto-draw/auto-send），改回按钮控制。

---

**一句话**：HL2 菜单用 MRTK 原生（PressableButton + ObjectManipulator + BoundsControl）替换 Unity UI；控制器逻辑（OnAddClicked 等）已现成，按钮事件接上即可；重构是 Unity 编辑器工作，代码侧不用改；按钮好了关掉自动模式。
