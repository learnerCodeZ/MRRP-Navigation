# HL2 开发迭代方式：原生部署 vs 全息远程（Holographic Remoting）

> 日期：2026-07-18
> 问题：每改一次 HL2（HoloLens2）应用，是不是都要重新部署一次？
> 结论：**原生部署是**；但开发期用 **Holographic Remoting（全息远程）** 可以免重部署、秒级迭代。

---

## 0. 一句话

改代码/Prefab 后想看效果，**原生部署**每次都要 rebuild + redeploy（分钟级，慢）；但 **Holographic Remoting** 让 Unity Editor 直接 Play → Wi-Fi 串流到 HL2，**改完再 Play 即时看**，且手势/头部追踪从 HL2 真机回传——**不用重新部署**，秒级迭代。

---

## 1. 两种方式对比

| 维度 | 原生部署（Build + Deploy） | Holographic Remoting（全息远程） |
|---|---|---|
| 每次改动后 | **rebuild（IL2CPP，几分钟）+ redeploy** | **再点一次 Play**，秒级 |
| HL2 上跑什么 | 独立 AppX 应用（**脱机**，演示用） | Remoting Player（**依赖 PC**，开发用） |
| 手势/头部追踪 | 真机原生 | 真机→回传 PC（**真手势**，非模拟） |
| 网络 | 不需要（脱机） | 需 PC + HL2 **同一 Wi-Fi** |
| 延迟 | 无 | 微小（局域网，体验接近真机） |
| 何时用 | 第一次验 build 链路 / **最终交付演示** | **开发期改 UI / 调功能**（主力） |

---

## 2. 原生部署：每次改都要 rebuild + redeploy

- 流程：Unity Build → 生成 UWP `.sln` → VS2022 部署（USB/WiFi/Device Portal）到 HL2。
- 改了**任何**代码/Prefab/资源 → 都得重新 Build（IL2CPP 编译几分钟）+ 重新 Deploy。
- 做完整 UI 美化（多次微调）如果全走这条路，每次几分钟，很痛。
- 优化：首构建建后 IL2CPP 增量编译快些；WiFi/Device Portal 部署比 USB 方便一点——但仍要重 build。

---

## 3. Holographic Remoting（开发神器，免重部署）

- **PC 上 Unity Editor 点 Play**，画面 + 音频**实时串流到 HL2**；HL2 的**手势、头部追踪、空间映射回传到 PC**。
- 改完代码/Prefab → **再点一次 Play** → 头显里立刻看新效果，**不 Build、不 Deploy**。
- 用的是**真手势**（HL2 回传），不是 Editor 鼠标模拟——所以手势画线逻辑能真实验证。

> 代价：PC + HL2 同一 Wi-Fi；HL2 跑 Remoting Player（**非脱机**，依赖 PC）；有微小延迟。**定位是开发调试，不是最终交付。**

---

## 4. 推荐迭代策略

```
① 先做一次原生 Build + Deploy —— 验证整条 build/deploy 链路能通（一次性痛苦）
        ↓
② 开发期改 UI / 调功能 —— 全用 Holographic Remoting（Editor Play 串流，秒级迭代）
        ↓
③ 定稿 —— 最后一次原生 Build + Deploy（脱机交付，演示用）
```

要点：
- **原生部署只做两次**：第一次验链路、最后交付。中间**全走 Remoting**。
- **UI 想改多少次都行**——Remoting 兜底，每次改完 Play 就在头显验证。
- 先验设备链路（最大未知），再用 Remoting 快速迭代（已知可行）。

---

## 5. Holographic Remoting 怎么开（MRTK2）

**HL2 端：**
1. HL2 微软商店装 **Holographic Remoting Player**（免费），打开它 → 屏幕显示 HL2 的 **IP 地址**。

**Unity 端：**
2. `ProjectSettings` 里 `isWsaHolographicRemotingEnabled` 从 `0` 改 `1`（或经 MRTK 菜单启用 Remoting Play Mode）。
3. 启用 **Holographic Remoting Play Mode**（MRTK 菜单 / OpenXR Remoting 插件），填入 HL2 的 IP。
4. 点 **Play** → Unity 串流到 HL2，HL2 上即看到应用 + 可用手势。

> OpenXR 路线：装 `com.microsoft.mixedreality.openxr` 后，其 Remoting Feature 也支持 Editor Play Mode 串流。

---

## 6. 何时用哪种（速查）

| 场景 | 用哪种 |
|---|---|
| 第一次验证 build/deploy 能不能通 | **原生部署** |
| 改 UI / 调手势 / 调功能（频繁迭代） | **Remoting** |
| 调 ROS-TCP 连接（HL2 连机器人） | Remoting 也行（HL2 经 PC 联网）；最终原生验证 |
| 给别人演示 / 论文录屏 / 脱机跑 | **原生部署**（脱机，不依赖 PC） |
| 出门前最终版 | **原生部署** |

---

## 7. 复盘要点

- **原生部署 = 每改必重 build + 重 deploy**（慢），是最终交付手段，不是日常迭代工具。
- **Holographic Remoting = Editor Play 串流到 HL2，改完即看、不用重部署，且真手势回传**——开发期主力。
- **策略：原生验链路一次 → Remoting 快速迭代 → 原生交付一次**。原生只做两次。
- Remoting 的限制：要 PC + 同 Wi-Fi、HL2 跑 Player（非脱机）、微延迟——所以是开发用，演示仍需原生部署。

---

**一句话**：每次改 HL2 应用，原生部署确实要重 build+重部署；但开发期用 Holographic Remoting（Editor Play 串流）可免重部署、秒级看效果、用真手势——所以原生只在"验链路"和"交付"各做一次，中间全走 Remoting。
